## 如何运行（测试人员请读这里）

**下载或克隆整个仓库后，用 Google Chrome 直接打开根目录的 `index.html` 即可。**

没有构建步骤、不需要安装依赖、不需要启动服务器、没有远程 CDN 或后端，所有脚本都是普通 `<script defer>` 本地文件，支持 `file://` 直接打开。首次打开会看到 10 条虚构演示记录。

可以照着下面的步骤走查核心流程：

1. **浏览**：首页顶部统计待寻找失物 / 待认领物品 / 全部发布数量；点“全部 / 失物 / 招领”切换类型，进行中的信息排在已解决之前，已解决记录保留并显示“已找到 / 已归还”标签。
2. **发布**：底部导航点“发布”，选择“我要寻物 / 我要招领”，选择物品分类，填写标题、地点、联系方式（带 \* 必填）。缺填或超长会标红并阻止提交；提交成功后进入成功页，新信息同时出现在首页和“我的发布”。
3. **搜索**：底部导航点“搜索”，输入关键词（命中标题 / 描述 / 地点任一字段，首尾空格不影响），可叠加物品分类筛选和“只看进行中”开关；无结果时有明确提示。
4. **详情**：点任意卡片查看详情，展示分类、地点、日期、发布者与联系方式；点“**复制联系方式**”一键复制（剪贴板不可用时自动降级，不会谎报成功）。
5. **更新状态**：在“我的”页或自己发布的信息详情页，点“**标记已找到**”（寻物）或“**标记已归还**”（招领）；已解决的信息还可以“重新开启”。首页、搜索、详情、我的发布读取同一份数据，状态处处同步。对别人的演示记录操作会提示“只能修改自己发布的信息”，不会静默失败。
6. **持久化**：刷新页面后，新发布的信息和更新过的状态依然存在（保存在浏览器 localStorage，键名 `campus-lostfound.v1`）。

脚本按 `js/core.js` → `js/storage.js` → `js/app.js` → `js/pages/search.js` → `js/pages/detail.js` → `js/pages/my-posts.js` 的顺序以普通 `<script defer>` 加载，不使用 ES module，因此可以直接以 `file://` 打开。

## 自动化单元测试

网页运行不需要 Node.js；只有运行开发测试时需要。安装 Node.js（18+）后，在项目根目录执行：

```text
node --test
```

测试使用 Node.js 自带的 `node:test` 与 `node:assert/strict`，**不需要安装任何 npm 依赖**。`tests/core.test.js` 与 `tests/storage.test.js` 共 31 个用例，覆盖：必填与超长校验、纯空格标题、非法分类 / 地点、关键词命中三个字段、组合筛选、只看进行中、空结果、排序规则、状态流转与发布者权限、XSS 转义、持久化读写、损坏 JSON 回退、非法记录过滤、写入失败回滚等。

2026-10-07 在 Node.js 22 上运行：31 个通过，0 个失败。页面布局与真实剪贴板权限需在 Chrome 中手动走查。

## 数据与限制

- 数据保存在**当前浏览器**的 localStorage（键名 `campus-lostfound.v1`）。更换电脑、更换浏览器或清除站点数据后，新增信息与状态不会同步。
- 程序只能区分“**本浏览器**发布的记录”（`ownerId` 是本浏览器生成的 `clientId`），不能验证真实身份，也不是跨设备共享的多人平台。
- 演示记录与联系方式均为虚构数据。请勿在公开信息里填写手机号、证件号码等敏感资料。
- 本次按要求**不实现**复杂后台管理、实名认证、即时聊天、地图定位。

## 附加特点

1. **一键复制联系方式**：详情页点按即复制，`navigator.clipboard` 不可用时降级为 `execCommand`，再不可用时明确提示手动复制。
2. **“只看进行中”开关**：搜索页可一键隐藏已找到 / 已归还的历史信息，与关键词、分类筛选叠加使用。
3. **状态文案区分信息类型**：寻物显示“标记已找到”，招领显示“标记已归还”，已解决记录可“重新开启”。
4. **组合筛选**：关键词 × 物品分类 × 信息类型（首页）/ 只看进行中（搜索页）。
5. **健壮性细节**：用户输入全部经 `escapeHtml` 转义；存储损坏自动回退演示数据；写入失败回滚并明确报错；无效 ID 的详情页给出提示与出口。
